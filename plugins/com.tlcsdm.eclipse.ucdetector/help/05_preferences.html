Preferences

Open Window > Preferences > Tlcsdm UCDetector. The preference page is organized in five tabs that mirror the original UCDetector preference page from www.ucdetector.org: Ignore, Detect, Keywords, Report and Other. Every setting on the page is described below.

Ignore tab

Filters used during analysis. Patterns are comma-separated and support the wildcards * (any number of characters) and ? (single character). When an element matches, it is skipped during detection.

Resources

Source folders
If a source folder matches one of these expressions, all of its contents are skipped. Useful for excluding generated sources or test source folders.
Packages
If a package matches one of these expressions, all classes in that package are skipped.
Derived files
Skip every class whose underlying file is marked derived in the workspace. Generated code is typically derived.

Classes

Matching name
If a class name matches one of these expressions, the class is skipped.
Implementing/extending
Skip classes or interfaces that implement or extend one of the listed types. Use this for framework callbacks (e.g. servlets, listeners) that are referenced reflectively.
Containing string
Skip classes whose source contains one of the configured strings. Useful when a marker comment in the file should disable detection.
Having a main method
Classes with a public static void main(String[]) method will not produce "unused class" markers, since they are usually launched externally.

Methods / Fields

Methods
If a method name matches one of these expressions, the method is skipped.
Fields
If a field name matches one of these expressions, the field is skipped.
Bean methods
Ignore Java bean accessor methods (getX, setX, isX). These are typically called reflectively and would otherwise produce many false positives.

Marked code

Code with Annotations
Skip code marked with one of the listed annotation types (for example javax.annotation.PostConstruct).
Deprecated code
Skip code marked with the @deprecated javadoc tag or the @Deprecated annotation. Disable to also review deprecated code.
Code with // NO_UCD
Skip code that has a // NO_UCD end-of-line comment. The comment is the recommended way to opt out a single member from detection. Disable to review existing opt-outs.

Detect tab

Decides which checks run and the warning level for each marker.

What to detect

Detect code with max number of references
Threshold of references below which a marker is created. 0 means dead code only, 1 means "at most one reference", and so on.
In classes / In methods / In fields
Per-element-type combo boxes (Ignore, Warning, Error) used as the warning level for the "few references" markers.
Detect code only called by tests
Mark production code that is only referenced from test code (typically code in source folders ending with test).

Use final

Possible use of final for methods
Detect methods that are never overridden and could be declared final.
Possible use of final for fields
Detect fields that are never reassigned and could be declared final.

Reduce visibility

For each Java element type a combo box decides whether to suggest reducing its visibility to protected or private. Applying these warnings on classes or methods can cause compile errors, so review the suggestion before fixing it.

Classes protected / Classes private
Visibility warnings for classes.
Methods protected / Methods private
Visibility warnings for methods.
Fields protected / Fields private
Visibility warnings for non-constant fields.
Constants protected / Constants private
Visibility warnings for static final fields.
Don't care about warning Access to enclosing type
Suppress visibility suggestions that would trigger the JDT compiler warning Access to enclosing type (synthetic accessor emulation).

Cycles

Max class cycle size
Maximum number of classes that may participate in a cycle reported by the Detect cycles command. Larger cycles are dropped.

Keywords tab

Configures whether class names are searched in non-Java files (text, XML, properties, ...). Use this when types are referenced only by name (e.g. Spring XML configurations or reflection).

Search class names in text files (slow)
Turns the file-based search on. Disabled by default because it slows down detection.
Use full qualified class name
Search for the fully qualified name (com.example.Foo). Reduces false matches.
Use simple class name
Search for the simple name (Foo). Fast but produces more false positives.
File name pattern to search
Comma-separated list of file name patterns, for example *.xml,*.properties.

Report tab

Controls where reports are written and which formats are produced.

Report directory
Directory in which UCDetector writes report files.
Report file name
Template for the report file name. The placeholders ${number}, ${project}, ${date} and ${time} are replaced at run-time.
Create xml report
Additionally write an XML report next to the textual report.
Browse reports directory
Open the configured report directory in an external file browser.

Other tab

Logging and miscellaneous settings.

Level
Log level for plug-in output (DEBUG, INFO, WARN, ERROR, OFF).
Log to Eclipse Console View
Mirror the log output to a dedicated UCDetector Console in the Eclipse Console view.
