Usage

This page describes every menu entry and every view contributed by the plug-in and explains what happens when you run them. For the per-setting reference of the preference page see Preferences.

Install the plug-in

  1. Open Help > Install New Software... in Eclipse.
  2. Add the update site https://raw.githubusercontent.com/tlcsdm/eclipse-ucdetector/update_site/.
  3. Select Tlcsdm UCDetector, finish the wizard and restart Eclipse.

Run a detection

  1. In the Package Explorer or Project Explorer, right-click a Java project, source folder, package, type or working set.
  2. Open the Tlcsdm UCDetector submenu.
  3. Choose one of the available actions described below.

The submenu only appears when the current selection contains Java elements (org.eclipse.jdt.core.IJavaElement) or an Eclipse working set. The selection determines the analysis scope: a project analyzes everything in that project, a package limits the analysis to its compilation units, and a single type limits it to that type.

Menu actions

The plug-in contributes a single top-level Tlcsdm UCDetector submenu to context menus on Java elements. The submenu groups four actions.

Detect unnecessary code

Runs the main UCDetector analysis on the current selection. The detector iterates over every Java element in scope and creates Eclipse problem markers for every finding it produces:

  • References – the element has no references at all (dead code) or only a few references (configurable on the Detect tab).
  • Visibility – the element could be declared with a more restrictive visibility, for example public → protected → default → private.
  • Final – a method is never overridden, or a field is never reassigned, and could be declared final.
  • Test only – production code that is only referenced from test code.

What happens after running it:

  • A background job named Detect unnecessary code runs and shows progress in the Eclipse status bar.
  • Each finding becomes a marker in the Problems view; the warning level (Ignore, Warning, Error) for every check is taken from the Detect tab of the preference page.
  • A textual or HTML report is written when the corresponding option is enabled on the Report tab of the preference page; the result message tells you how many markers were created and where the report was written.
  • If Log to Eclipse Console View is enabled, log output appears in a dedicated UCDetector Console.

Clean markers

Removes every UCDetector marker that exists below the current selection. Use this command before re-running detection on a project, or when you want to clear stale markers without changing any code. It does not modify source files.

Count elements

Counts the Java elements that would be considered by Detect unnecessary code for the current selection. The result is printed to the Eclipse Error Log and the UCDetector Console (when console logging is enabled). Use it to estimate how large the next detection run will be without actually creating markers.

Detect cycles

Searches the selected scope for cyclic class dependencies. Each cycle is reported as a tree in the Cycle View (see below). The Max class cycle size preference on the Detect tab limits how big a cycle may grow before it is dropped.

Views and other UI components

Package Explorer / Project Explorer
Selects the Java project, source folder, package, type or working set that the plug-in should analyze. The right-click Tlcsdm UCDetector submenu is the entry point for every command.
Cycle View (Window > Show View > Tlcsdm UCDetector > Cycle View)
Displays the result of the Detect cycles command as a tree of cyclic class dependencies. Selecting a node opens the corresponding type in the Java editor so you can break the cycle.
Problems view
Shows every marker created by the detection. Double-click a marker to jump to the affected source location. Markers can be filtered using the standard Eclipse filter dialog of the Problems view.
Quick Fix (Ctrl+1)
Available for many marker types. Applies the suggestion of the marker (delete a member, change visibility, add final, add a // NO_UCD comment, etc.) directly from the Java editor.
Preferences page (Window > Preferences > Tlcsdm UCDetector)
Configures filters, detection modes, markers, reports and logging. See the Preferences page for a per-setting reference.
UCDetector Console
Displays plug-in log output when Log to Eclipse Console View is enabled on the Other tab of the preference page. Open it from the Console view's Open Console drop-down (UCDetector Console).

Review results

UCDetector creates markers in the Eclipse Problems view. Double-click a marker to jump to the relevant source. Many findings also provide a Quick Fix via Ctrl+1.

To reset the workspace state between runs, use Tlcsdm UCDetector > Clean markers on the projects you want to re-analyze.

Headless mode

UCDetector can also run as the Eclipse application com.tlcsdm.eclipse.ucdetector.detect. See Headless Usage for the command line workflow and the repository's launches/ folder for a ready-to-use Eclipse launch configuration.
